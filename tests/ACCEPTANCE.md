# 发版验收三路（Acceptance Protocol）

> v7.1.1 起固化的发版前验收流程。每次发版（tag 之前）必须完整走一遍。
> 三路子代理**互不看对方报告**，各自独立产出报告；三份报告 + 主控终裁对齐后才允许进入发版链路。

## 为什么是三路

单一验收者既有盲区：自己出题自己验容易自嗨、实施者自测容易被「让测试变绿」迁就断言、逐条核对最容易被跳过。三路从三个正交方向夹击：

| 路 | 干什么 | 防什么 |
|---|--------|--------|
| 路一【矩阵核对】 | 拿本次需求清单，逐条映射到具体测试用例（文件+用例名+断言行），找出**漏测**与**弱断言**；只读代码与测试，不跑不写 | 漏测 |
| 路二【独立复跑】 | 全新会话、只读代码，**自己重跑** unit + e2e 全量，并抽查断言强度（对照 git diff 看断言是否被弱化迁就实现） | 断言被弱化迁就 |
| 路三【对抗探测】 | **不看矩阵清单**，自己从用户/攻击者视角设计 ≥10 项探测（边界/竞态/注入/过期/跨端一致性），真跑真验 | 自嗨式覆盖 |

## 通过标准

1. 三份报告全部产出，P0（会坏）= 0；P1（不一致/边界坑）全部修复或由用户拍板接受
2. 主控逐条核对三报告与需求清单，形成终裁记录
3. 主控本人终闸复跑全量（unit + e2e）全绿
4. 以上齐了才允许：commit → tag → push → SFTP 部署 → 双域核验 → CI

## 各路操作卡

### 路一【矩阵核对】
- 输入：本次版本需求清单（主控提供，逐条编号）
- 动作：对每条需求，在 tests/ 里指出覆盖它的用例（文件:行号）；找不出用例的记「漏测」；有用例但断言只验证存在性不验证行为的记「弱断言」
- 禁止：改任何文件、跑测试后下结论（只静态核对）

### 路二【独立复跑】
- 动作：`cd tests && node --test unit/*.test.js` 与 `node --test e2e/*.test.js`（受管 node 全路径），记录 pass/fail 数；`git diff` 抽查本次改动涉及的测试文件，确认断言没有被顺手改弱
- 发现 fail → 原样报告，不许自行修

### 路三【对抗探测】
- 动作：不看路一清单，自己列 ≥10 个探测点并真实验证（jsdom 单测、临时脚本、curl 探测线上皆可；临时脚本用后删除）
- 视角：往坏了用（空输入/超长/过期/并发/跨端不一致/特殊字符/单位数月日）

## 与既有纪律的关系

- 全测试纪律（改码必跑 unit+e2e）不变，三路是**发版前**额外闸门
- 三子代理可并行实施+Verifier 单路验收的旧模式在 v7.1.0 用过；v7.1.1 起正式以本文件为准
- 用户拍板记录：2026-09-07，载体 = 本文件 + memory 发版纪律
